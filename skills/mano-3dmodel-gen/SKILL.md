# 加载纪律（唯一入口，先执行）
- 本文件是 root。先判任务类型，只加载命中的部分；专项最多再加 2 个，总数 ≤ 3。禁止一次全装——全装反而找不到东西。
- 措辞只用三档：MUST 必须 / SHOULD 应当 / NEVER 禁止。每条规则要么指向一个命名默认值，要么给出数字阈值。没有默认值的“真实一点”不算规则。
- 默认值原则：用 simulator 的既定值（见 §2–§4），除非用户明确要求，不发明新值。来源没写数字的，一律标，不冒充来源值。有原片时先 1:1 抄源码（见 §6），NEVER 未抄先重推导。

## 1. 听懂一句话 → 场景简报（写代码前，输出 6 行）
- 场景：用户的一句话属于哪个行业（施工 / 物流 / 机场 / 工厂 / 仓库 / 港口 / 其他）——行业决定机器角色，不决定具体机型。
- 主体：画面里最核心的 1 个主角（一个流程 / 一台机器 / 一批货物），只定一个。
- 动作：主角在做什么（挖 / 运 / 卸 / 装 / 浇 / 升），用动词写，不写形容词。
- 情绪：3 个词命名场景感觉，禁止用“真实、高级、震撼”——先定感觉再选配色与节奏。
- 时长：总时长 + 关键节拍点（第几秒发生什么），先写数字再动手；默认 38–52s，不取整更佳（如 43.7s、39.4s）。
- 出口：Web 3D 互动页（默认）/ 40s 影片 / 单帧效果图，三选一。
- 场景提示词模板（扩写后直接可用）：`[行业]的[主角]正在[动作]，[情绪]，总长[时长]；一个相机 fov 28°，地面薰衣草，车身蓝，作业件黄；主角旅程：[起点]→[终点]。`
- 细节提示词模板（每台机器一行）：`[角色]：[机型]，长×宽×高=[数字]，底盘=[轮式 R0.75/履带]，作业件=[部位]黄，动作=[动词]，路径=[弧线/直线]+smootherstep。`
- 自检：把自己的第一反应（机型、配色、镜头）写下来并否掉一个——第一反应就是训练语料的中位数；再问一句：这个场景是为流程服务的，还是只为堆模型。

## 2. 定场景规格（五规则 + 视觉系统，代码只准引用）
- 五规则（simulator 的逻辑，不是装饰）：一个相机（全程一个角度，只平移缩放，不切镜、不环绕）；玩具比例（大形体、软边、去细节）；两色（蓝 + 白，薰衣草地面，黄只给作业件）；真软件在上（顶栏、KPI 卡、跟踪条、车队表，数字读自场景状态）——仅产品页/控制台类交付物，见 §5；游戏式选中（线框 + 脚下发光 + 地面路线）——仅产品页，纯模型页一律移除（见 §5）。
- 调色板：地面薰衣草 #d5def7；车身蓝 #3166ea；作业件黄 #f2b33a；轮胎 #1f2433；玻璃 #22304f；履带 #2a2f40；树冠 #7fdaa0；选中线框 #3f6ff0。
- 渲染：Neutral 色调映射、曝光 0.93；半球光 1.0（#f3f6ff/#c7d0ee）；太阳 2.2 白色；阴影半径 6；雾 700–1400。NEVER 用 ACES（会把薰衣草拉成灰）。
- 相机：透视 fov 28°、方位角 38°、俯仰角 36°；首帧目标 (12, 3)、距离 118；画面偏移 sx −110、sy +26。相机参数（fov/方位/俯仰/距离/view offset/骑车偏移）照源码原样抄，不可凭感觉改；逐帧对照原片静帧验收构图。
- 布局：以地块矩形为唯一基准框，统一推导围栏四边、道路、大门、搅拌站、Plot 的位置与朝向，禁止逐段手算；布局数字先读源码写进规格表再动工，禁止猜尺寸；车辆停放点用实测地面高验证（车轮须全落在平地上）。
- 单园区：场景只有一个园区；加工、装填、砌筑等作业全在园区内；道路与绿植与园区等长，不外延。
- 材质：全部盒子用圆角盒，倒角 = 最短边 × 12%；车漆 clearcoat 0.35；粗糙度 0.55，玻璃 0.12；NEVER 用 flatShading——玩具感来自大圆角和清漆，不是面片化。
- 压低：36° 相机看高架子只看见架子、看不见活——动作一律放地面；全场最高 ≤9 m；唯一的高物放侧面。
- 场景元素（按需取，不堆）：围挡 2.2 m、大门 8 m、临建 6×2.5×2.9 m；土堆 34° 休止角（主锥 + 3 小锥，顶圆化，侧面比顶部深）；基坑高度场（40×28 m、深 4 m、45° 坡壁、0.28 m 网格 + 逐顶点色）；树（棒棒糖形，干 2.7 m、冠 [2.0, 2.55, 2.0]）。

## 3. 模型词汇（通用建造器，不锁定具体物品）
- 每个模型都是一个返回 Group 的函数：rbox（圆角盒）/ cylinder / sphere / cone / extrude / tube；NEVER 手写顶点堆形状。不要发明外观：先拆一个已跑通的参考（每 3s 一帧的 contact sheet），把它的规则写下来，再按规则建。多部件结构（搅拌站/建筑）放进同一个 group 再整体定位，部件用组内局部坐标。
- 角色映射（先定角色，再选机型，NEVER 先抄一张机型清单）：搬运 = 轮式载具（统一轮胎 R 0.75、宽 0.64）；举升 = 铰接臂 + 解析 IK（动臂/斗杆/铲斗各带液压杆）；浇注 = 旋转筒（Catmull-Rom 光滑轮廓 + 溜槽）；平整 = 履带底盘（履带板 0.19×0.075、间距 0.34）；堆叠 = 叉齿 + 门架。
- 尺寸规则：每台机器先写 3 个数字（长/宽/高）再建模；黄色只给作业件（铲斗、动臂、料斗、筒、铲），车身/驾驶室/底盘一律蓝。每台机器先定前向轴（读源码的 front/朝向约定）再摆工作件，工作件须朝向行进方向、领先于车体；载荷按源码形态与缩放公式建（单堆 + scale 随装载量变，冠顶须高出斗沿）；实例化圆柱/条沿某方向时，先把长轴旋到该方向再缩放，数值验收：量两端世界坐标（水平条两端须同高，竖立即 P0）。
- 地形：坑、坡、堆一律用高度场或锥体，NEVER 拼盒子假装地形；水面用透明平面 + 涟漪环，NEVER 用实色块。
- 背面补全：单视角看不到的背面按同色板、同比例合理补全，并标注为“补全，非 1:1”；NEVER 猜一个不存在的零件。简化零件几何时检查内部细节（衬里/湿料）是否被埋；若埋，放到可见面并只在相关时显示。
- 人物：simulator 原项目没有人物模型——NEVER 凭空加工人；如需人物，按玩具比例另做并注明新增。

## 4. 时间轴：一天的工作写成 render(t)
- render(t) 是时间的纯函数：任意一秒乱序渲染结果相同；无物理、无随机定时、无帧间状态；车辆按路径弧长移动（CatmullRomCurve3，向心参数）、两端 smootherstep 缓动；倒车时车头朝向与切线相反；被搬运的物品每帧从当前持有者重新定位；背景车辆共用同一时钟。路径逐点校验：禁止相邻/首尾点重合（尖点）；切线须与道路轴线平行，车辆全程在车道内、车身平行于路；只画源码定义的路线，不自造；路线带逐点贴地（heightAt + 0.06），禁止固定 y。
- 浇筑/抛物：带俯仰/运动的坐标系里算抛物线，照源码原公式（溜槽真实方向做初速 + 落点相对组原点的高度做落差），不用完整 worldToLocal；数值验收：流起点 = 溜槽口世界坐标，落点 = 目标面；浇筑动作靠湿区圆盘 + 溜槽口灰色表达，不只看流。
- 先定主角旅程（一条主线，如一车混凝土从搅拌站到浇筑点 / 一个集装箱从机腹到货架），再排 3–5 个事件，最后定点击时刻（间隔不均匀，施工场原值 1.2/5.2/9.3/13.0/14.1/16.1/28.3/33.8/34.9/40.0s 仅作间距示范，新场景按事件重排）。
- 首帧必须已有东西在动（产品页：UI 全画好）；总长 38–52s。

## 5. 交付：Web 3D live 站点就是交付物
- 先定交付性质：模型展示页 = 全屏 canvas 一个，零 DOM 覆盖层（标题/KPI/详情卡/播放条/字幕/按钮一律不默认出现，须用户明确要才加）；UI 面板与选中/高亮覆盖层（线框/发光/地面路线）只在产品页/控制台类交付物里出现。每轮修完即发布，发布后核对线上与本地 bundle md5 一致，禁止攒轮次。
- Web 端 3D only，代码构建层；NEVER 用 Blender 或本机渲染路线；NEVER 导出帧或 MP4。
- 文件分工（仿 simulator 的 -shared）：style（调色板 + 共用材质 + 圆角盒 + 舞台）；world（布局 + 时间表 T + 每条路径 + pose(t) + 碰撞体）；ui（顶栏/KPI/跟踪条/车队表，仅产品页）；select（线框 + 发光 + 路线，仅产品页）；film（相机关键帧 + 点击 + 卡片，仅产品页）。
- 统一契约：renderAt(t) 驱动同一批镜头；播放器含自动循环、空格键静默切换（产品页另加播放/暂停、进度条、时间）；固定 1280×720 构图，手机端原样显示、无横向滚动。
- 分层：3D 用 Three.js/WebGL2；UI 面板与地面路线用 Canvas/SVG 画；单帧效果图可用 SVG 导出。
- 打包：esbuild 打成单个 IIFE bundle.js，页面用普通 <script src> 引入；NEVER 用 importmap / type="module" / 动态 import。
- 分工：两人并行——A 先按参考图 1:1 对齐一台主角机器，B 建其余；镜头每镜 5s、硬切，镜内平滑移动；先定相机再投标注；fov 28° 裁得比想象紧，近景先拉远再验。

## 6. 验收（原项目的检查法，最多 3 轮）
- 首帧定生死：t=0 时整场中距全景（产品页：UI 全画好）、有东西在动、无控制台错误、无 NaN（float32 边缘的 Math.pow(负数, 分数) 会出 NaN，底数先 max(0,·) 钳住；交付前扫全场顶点，NaN 须为 0）。
- 先 1:1 抄源码再建审核：有原片时，场景模块哈希与源仓库逐文件一致，NEVER 未抄源码先重推导；重推导、凭感觉改参数即 P0。
- 逐帧对照：t=0/5/10/16/20/30/40，同一视口/DPR，capture 模式暂停循环后截图；先遮掉选中标记与 UI 区域再算像素差，差 >0.1% 即 P0，须定位差异区域；每轮先列真 bug 再修，最多 3 轮；第 3 轮仍有 P0（主体遮挡、相机穿模、帧不同步）即停并上报，不硬修。探针帧验收：围栏闭合、四边平行于地块边与道路；车辆全程在车道内、车身平行于路；多部件结构须读作一个连贯装配体；载荷冠顶高出斗沿；浇筑帧溜槽口须有灰色；飘带不得浮在坑/坡道上方；线框须紧贴当前选中物。
- 代码值核对：阴影贴图/半径、灯光/曝光/雾、相机、筒轮廓与溜槽、浇筑流、围栏/基坑/土堆尺寸，逐项对源码值（含 file:line）；1:1 构建按构造通过，任一不符即 P0；抄覆盖值，不抄底座值。
- 覆盖层与探针：选中框每帧对当前姿态现算世界 AABB，禁止缓存局部中心；选中/高亮组初始一律隐藏；t=0（首个点击点前）必须单独探针验收，捕捉 stray 标记；定帧截图前先暂停播放循环，直播检查前再恢复，帧号须与实际渲染时刻一致（用点击边界点校验）。凡“像穿模/错位”的，先查源码动作表与布局数再定性；核实无误后记“核实不是 bug”，勿修；审核脚本自身报错先溯源脚本期望值，勿直接判重建缺陷。
- 碰撞扫查：每次改路径后扫一遍——每 0.1s 用各物自带几何的定向包围盒检查，树按点、车对墙；盒在干净状态下算（勿在中途渲染后算），允许清单只放源码确认的接触；注出“理应接触”的配对（如铲斗入土、叉齿入货盘）。
- 模型/动画核对：水泥车几何、浇筑流路径/时序/湿区逐项比源码，t=27.4/30/33.6 三帧实测。
- 门禁：审核脚本输出 JSON 报告 + 一页摘要，存项目目录；任一 P0 即 FAIL，不交付。
- 豁免记录：每项偏离写进 CHANGELOG，不藏。

## 7. 两个压缩案例（只示范角色映射，不当模板抄）
- 施工工地：角色 = 挖（挖掘机 IK 臂 + 履带）/ 运（翻斗车，车斗可倾 50°）/ 浇（搅拌车，筒 Catmull-Rom 轮廓 + 溜槽）/ 围（围挡 2.2 m + 大门 8 m）/ 堆（土堆 34°）；主线 = 一车混凝土从搅拌站到浇筑点；事件 = 基坑挖开 → 钢筋铺开 → 楼板浇筑 → 砌块墙升起。
- 飞机物流卸货园区：角色 = 运（行李牵引车 + 传送带车）/ 举（叉车门架 + 货盘）/ 卸（飞机货舱门 + 升降平台）/ 存（货架阵列 + 集装箱）；主线 = 一个集装箱从机腹到仓库货架；事件 = 飞机进位 → 舱门开 → 货物下传送带 → 叉车入库 → 货架码齐。

## 硬禁令
- NEVER 锁定具体物品清单（叉车、塔吊、搅拌车只是角色的一种实现，不是必选项）；NEVER 把 simulator 的某个场景 1:1 复制成新场景。
- NEVER 用 ACES、flatShading、逐帧状态、未播种的随机数、墙钟时间。
- NEVER 凭空加人物、NEVER 编造数字（面积占比、转速、价格、链接），来源没写的标。
- NEVER 找借口：Web3D 项目只需要浏览器，不需要显卡；加载慢是初始化太重，先减初始化，不解释。

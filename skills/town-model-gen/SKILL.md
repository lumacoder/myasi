# AITown 建筑与园区 JSON

这份 Chat 版以 AITown town-model-gen 2.4.0 的建模规则为基线。先读 [JSON 约定](references/model-json.md)，再按用户想导入的对象选择产物。

| 对象 | 产物与参考 |
| --- | --- |
| 普通小楼、静态设施、口袋公园 | `aitown.building/1`。以 [JSON Schema](references/building.schema.json) 为字段依据。参考 [街角花店](examples/corner-florist.json) 或 [口袋公园](examples/pocket-garden.json)。 |
| 大型园区、机械主角、有关节的设施 | 先做米制场界、接路和活动范围，再交结构化 Brief。用户提供现有驱动及模型格式时，按该格式生成布局 JSON。 |

## 生成步骤

1. 从需求提取主画面、功能链和尺度。园区先定边界、入口与路线，再分区摆放。把用户未指定且会影响成品的尺寸或布局记为设计选择。
2. 用形体区分主体、支承和小件。先搭地面、主体和入口，再加识别细节与生活痕迹。每处细节都应服务于场所功能。微缩画风用浅色主体、圆润边缘、局部玻璃和少量强调色。建筑用现有 `colorway` 与 `mat` 角色。
3. 输出可保存的 JSON。普通建筑使用明确的 `parts`、稳定 ID 和米制坐标。大型园区先核对路径、接路、围护与全程扫掠，再安排主角和动作节拍。
4. 检查字段、引用、构件越界、贴地支承、入口到街道的通行和体量预算。能运行检查时记录结果。仅能检查文本时，说明待跑的工程验证。

默认提供一个 JSON 代码块或下载文件，再附占地、设计选择和验证状态。用户要求纯 JSON 时，只输出合法 JSON，保留原生字段。

# 先选画面机制，不先选schema

每个作品写一个小适配器就够；不要为一次画面造通用引擎。把几何构造、时间状态、绘制分开，使最弱帧能单独重建。

|视觉问题|可实现的专用机制|先做的风险帧/反例|
|---|---|---|
|毛笔叶片不是光滑icon|曲线中心线→弧长采样→随压强/墨量变化的法向宽度→闭合轮廓；沿笔向短飞白；纸纹静止|放大起收笔；纹理不能把叶片吃碎，不能只叠全屏noise|
|绳/绸缎有弧长与方向|重采样中心曲线，带宽与切线法向，沿弧长生成褶皱/高光|曲率最大处不翻面；不能用几个圆点声称是布|
|角色主动而不是被搬走|关键剪影、准备/接触/发力/释放分期；根运动由驱动事件求出，IK只处理够到/锁点|最大压缩、接触结束、空中换脚；删除驱动应改变根运动|
|粒子形成可辨识主体|从目标轮廓/密度场采样；分布、连接和遮挡服务轮廓；明确前后态拓扑|缩略图冷读；粒子多不等于主体出现|
|机械/空间叙事|真实层级几何与局部轴，镜头揭示装配关系，必要时Three.js/WebGL|最复杂遮挡处和转轴极值，Canvas不能假装全3D|
|公式/解释动画|同一可见对象跨阶段保留身份；路径重采样、解析历史轨迹、标注围绕因果|观众能否指出前一状态如何成为后一状态，不是标题卡串联|

## 技术选择不是能力承诺
- Canvas2D：程序轮廓、笔触、轻量角色与图形，交付无依赖HTML方便。附带 `render_project.py` 直接支持它。
- SVG：需要文字/矢量路径、清楚边缘和编辑时；另备截图/栅格化协议。
- WebGL/Three.js：遮挡、透视、材质/光照确实参与表达时；依赖可用性和导出另核实。
- Manim：数学对象与演算明确时；不要用它的默认排版替代画面设计。技能不自动安装或下载这些框架。

## 最小适配器协议
```js
// 初始化可异步，但必须显式完成；导出时禁止requestAnimationFrame覆盖seek。
window.renderAt = function(t) {
  if (!Number.isFinite(t)) throw new Error('finite time required');
  // state=deriveFromAbsoluteTime(t); draw(state); 不累加上次帧状态。
};
window.READY = true;
```
Canvas内在像素尺寸须与导出尺寸一致。若需字体/资产，初始化先await加载，失败不能设READY。渲染函数本身可async，捕获器await它。附带示例无外部字体/位图/音频。

## 对“细节”的预算纪律
先解决主体身份、动作/变化和视觉焦点；再改材料、二级运动与边缘。墨量、飞白、透光等细节必须来自同一造型坐标系，不能成每帧乱闪。历史/随机均可用解析采样或固定种子索引，反向seek不应改画面。不要把“所有可能机制”全装进同一个作品。

## 阶段衔接不是“过阈值就放行独立时钟”
支撑路径画到节点后才长枝、脚接触后才推进冲量等情境，阶段起点应由事件到达时间/接触事件推导。先跑另一个全局ease，再用布尔门挡住，开门时可能从0跳到20%，即使“没有漂浮”测试通过也不连续。能解析反求就反求，不能则使用固定步长预计算并可seek；专门检查切换前后。水墨案例保留了这个真实故障与修正记录。

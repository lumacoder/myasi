# Web 3D 直播交付

网页本身就是作品：打开即播，不导出帧、不产视频文件。以下规则与 SKILL.md 第 5、9 步配套，按需加载。

## 介质判断：按题材断，不按顺手断

- 真 3D 题材（产品拆解、立体场景、带纵深的空间叙事）果断用 Web 3D（Three.js 写在网页里）。用 2D 画 3D 题材基本属于判断错误；反之，平面图形/手绘题材也不必硬上 3D。
- Web 端 3D 只在代码构建层实现：几何、材质、灯光、相机全是代码。不走本地机器/离线渲染器路线（不装、不调、不渲染导出）。
- 介质是创作决策，写进导演简报的不可变约束；一旦定了不中途换回 2D。

## 交付物：页面 + 播放器

- 交付 index.html（结构、字幕、标注、标题）+ 播放逻辑；打开即自动播放，按片长循环。
- 播放器是页面的一部分，不是导出器的替代品：播放/暂停、进度条（可点播）、时间显示、空格键切换。样式与片子一致，不另起一套 UI。
- 直播循环用真实时钟驱动 `renderAt(t)`（requestAnimationFrame）；`renderAt` 本身保持纯函数，播放器只负责给它喂时间。

## renderAt 契约扩展到 Three.js

- 同一契约：显式 `READY`，纯 `renderAt(seconds)`，固定种子，从绝对时间计算一切。相机位姿、层分离、灯光、景深焦点、标注位置都是 t 的函数，不留任何依赖墙钟或未播种随机的量。
- 场景数据化：几何、层、标注、字幕、尺寸全部写成数据表，镜头函数只读表、不在镜头里现造物体。加镜头不改场景，加场景不改镜头。
- 逐帧驱动约定：`?drive=1` 时不启动直播循环。逐帧驱动器（seek + 截图 + 探针）用这个参数保证确定性：同一 t 两次渲染像素相同，乱序 seek 相同。

## 标注投影顺序（必修）

- DOM/SVG 标注（引线、尺寸线、标签）必须在当帧相机就位后投影。顺序：算镜头位姿 → 设相机 → `camera.updateMatrixWorld(true)` → 投影标注 → 渲染。
- 错序的症状：标注在镜头切换的第一帧飞出画面、尺寸线斜穿全屏、标签锚点落在空处。修法不是调标注坐标，是调顺序。
- 标注锚点必须落在实物上（物体的点、边、孔），不落在两个物体的空隙里；标签位置夹取在画面内，不出框。

## 打包：ES 模块先打包再交付

- 纯前端页不依赖运行时的模块加载：ES 模块先用打包器打成一个 IIFE 文件。
- `esbuild main.js --bundle --format=iife --minify --outfile=bundle.js`
- index.html 用普通 `<script src="./bundle.js"></script>` 引入。不用 importmap、不用 type="module"、不用动态注入（`document.createElement('script')` 也不行）。
- 交付文件清单：index.html + bundle.js。打包器、源码与 node_modules 不进交付物。打包后实测：逐帧驱动探针相同、真实播放前进、关键帧画面与打包前一致。

## 验证：沙箱慢是环境问题，不是页面问题

- 沙箱无 GPU：软件渲染下单帧数秒，平台自动截图可能 15 秒超时。这是沙箱限制，不是页面问题。
- 验证分开做：风险帧（镜头边界、标注出现时刻、标题卡）逐帧冷读；探针相同（乱序 seek 像素一致）；直播播放两帧不同、时间标前进；长超时单独验加载（READY、零控制台报错）。
- 如实标注未验证项（例如“真机流畅度未在沙箱复验”）。不为通过自动截图改加载方式、不降级画质、不改视觉。

## 移动端

- 构图按交付尺寸定；手机上是否改编由用户定。没得到改编许可时，固定构图原样呈现（无横向滚动），不擅自改视觉。

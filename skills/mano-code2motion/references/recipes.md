# 从叙事到镜头的配方（不是一键模板）

先写语义计划，再把执行器能表示的部分编译成 spec。以下超出 v1 的属性**不是可直接喂给 v1 的 JSON**。

## 叙事：孩子拉父亲看海
- 意图：父亲注意力从手机转向女儿。先让观众读清视线/手部接触，再一起动。
- 节拍候选：静止建立关系 → 女儿预备 → 手接触 → 父亲躯干滞后 → 共同加速 → 到达。时长按总片长/可读性分配，不规定所有片子同一秒数。
- 中间层：每拍列起止秒、主对象、关键姿势、接触点、视线、次级跟随；先画剪影和接触表，再绑定，不让“丝滑”盖过故事。
- 检查：不看字幕能否辨认是谁主动；手接触后距离不能漂；动机不能只存在于说明文字。

## 角色与材质：重物落地，软绳跟随
- 身体根节点先下落，接触帧明确。接触后根位移受地面约束；软部件可以滞后，但刚体不压成橡皮。
- 步行/跑步：接触、下沉、经过、腾空/高点分别设计。支撑阶段将脚底锁在世界坐标，用 IK 解膝与髋，不是给脚再加一个 ease。前后脚切换检查滑动 px 与膝翻转。
- v1可做重物的根平移对照；骨骼、接触约束、遮挡、脸/手造型需另做适配器。原画质量与运动质量分开评，不用大量压色路径冒充干净人物。

## 镜头：有理由的推镜
- 意图：从关系转向情绪。固定叙事落点，推镜服从构图/阅读，不是每个镜头都缩放。
- 2D可把世界点通过统一相机变换投影；3D需真实焦距、距离、近远景透视。推轨与变焦的透视效果不同，dolly zoom 需焦距和相机距离配合并验证主体屏幕尺寸。
- 检查：主角是否跑出安全区；字幕是否稳定；视差是否方向一致；镜头不能抢角色动作的注意力。

## 流畅转场：父女跑步 → 海边画画
- 先选连续的视觉锚（手势、方向、形状、亮度或声音），再选匹配剪辑/遮挡切/短溶解。叙事断点可以直接切，非要模糊反而脏。
- 溶解以统一时间函数交替 alpha，不做两张图各自叠加的非归一化亮度；在线性光混合与普通 sRGB 混合间明确选择，检查中点发灰/亮度突变。
- 检查前后各数帧：视线落点、运动方向、地平线、曝光、遮挡边缘；转场时间只给候选范围，不把 UI 的 150–300ms 当影片通用标准。

## 特效：有冲击，不靠抖满屏
- 接触事件绑定同一个时间点。主体先提供可读力线；粒子速度方向、寿命(s)、阻力、重力(px/s²)从事件派生；屏幕震动用衰减包络、固定噪声种子。
- 候选初值：震动幅度占画宽 0.2–0.8%、持续 0.08–0.25s；仅是起点。字幕/界面可不跟镜头震动；光敏和 reduced-motion 用户需无闪烁/无震动替代。
- 先关闭全部特效检查动作是否成立；成立后再逐项打开。粒子不能掩盖穿模或接触时刻错误。

## 从一个词到三种实现的示范
“圆球移动得丝滑”：①轻质UI球→短时 ease + 清晰停顿；②玻璃球水平滚动→守住转动/平移关系，非任意缓动；③镜头追踪球→保持球世界运动，平滑相机而非改物理。先明确语义分支，再改 duration/轨迹/接段速度。
“电影感”：可来自构图、镜头动机、节奏、曝光与景深的共同组织；24fps、黑边、颗粒、模糊都不是充分条件。

# 资源卫生：边做边清
目标：开发不在磁盘与内存上留双负荷；清理可解释、可追溯、不误删。

## 基线与预算
- 开工记录：`df -h`、`free -h`（Windows：`Get-PSDrive`、任务管理器）、项目目录大小、自己启动的 PID/端口。
- 收尾对照基线，增量要能解释；渲染/构建前看可用内存，留 ≥25% 余量；OOM/swap 先降并发。

## 产物分级
| 级别 | 例子 | 处理 |
|---|---|---|
| 源码/锁文件/最终成品 | `src/`、`package-lock.json`、终版视频 | 保留，入库或交付 |
| 可再生 | `node_modules/.cache`、`dist`、`out/frames`、`__pycache__`、QA截帧 | 用完即删，进 `.gitignore` |
| 被取代 | 旧压缩包、旧中间视频、`*.bak *.old *-copy`、`v1/ final_final/` | 交付后删；大文件只留终版+一个上一版 |
| 唯一副本/用户数据/他人目录 | — | 不删，先问 |

## 规则
- 迭代用 git commit/分支/tag 留痕，不复制整目录；同一文件不在多处存放。
- 服务谁起谁关：dev server、watcher、浏览器、渲染进程验收后停止；交付列出仍在运行的服务及理由。
- 删除用明确路径，先列清单再删；禁止宽泛 `rm -rf *`、通配到家目录或系统目录。
- 不动宿主自身服务（远程桌面、同步、连接器）；不确定归属时只报告不处理。

## 清理报告（交付必含一行）
清理：删除 <路径/类别>，释放 <大小>；保留 <最终产物>；仍在运行 <服务:端口 / 无>。
